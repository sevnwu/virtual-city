⚠ **建模方案有三个互斥选项，必须先选**（`:232`）：

```
(a) **匹配模型**（Mortensen-Pissarides 简化）：空缺 × 求职者 ⇒ 匹配率 ⇒ 工资议价
    ＋ 最贴近"失业率是内生"的项目关切；－ 参数多（匹配弹性/议价力），小样本难标定

    ＋ 参数最少（α 有文献值 0.4~0.6）；－ 没有企业异质性，"企业纾困"仍无对象
(c) **局部市场**（按行业/区切若干子市场）：折中
    ＋ 可表现"行业间工资差"；－ 算力与标定成本最高
⭐ **建议：先 (b) 再视需要 (a)** —— 理由是算力约束（本项目 6 核 / 15.9 GB）
   与"先把价格端接上"这个最小目标；(a) 的匹配弹性可以后加。

### 3.9 ⭐ 推荐方案 (b) 的**最小可施工骨架**（明天可直接照做）

```
【新增 3 个状态】
  city.cap     = 资本存量 K（元）           · 不在 ARR 也可（先跑通，再决定是否持久化）
  city.tfp     = 全要素生产率 A             · ⭐ 已由技术层提供 `cityTfpOf(year)`
  city.wageIdx = 工资指数 w/w0（相对基准年） · 一维，代表"市场工资相对行政公式的偏离"

【每月（与既有"月度调薪"同节奏）】
  Y  = A · K^α · L^(1-α)                    // L = 在职人数 · α 取 0.5（文献值 · 待标定）
  w* = (1-α) · Y / L                        // 边际劳动产出 ⇒ 市场工资
  wageIdx → w*/w0_idx（慢速收敛，避免月内跳变）
  投资 I = 储蓄 S · (1 - 消费倾向)           // ⚠ 先简化为"居民财富增量的一部分"
  K' = K·(1-δ) + I                          // δ = 折旧率（文献 5%~10%/年）

【接到既有代码的**唯一**接口】
  `incomeOf` 末尾：`× wageIdx`（与 ② 技术增长的写法**同构**：
    ⭐ 走"链尾包装"而不是逐条改 5 条 return 路径 —— 本仓栽过多次）
  ⚠ 且必须遵守 §五·① 的纪律：**关时连求值都不能多一次** ⇒ 包装层里先判开关再求值。

【为什么这样最小】
  · 不改 `JOBS[].inc`（那是"行政公式的骨架"）⇒ 只加一个**指数**乘数
  · 不改失业率决定机制（那是 (a) 的活）⇒ 先只把**价格端**接上
  · ⭐ **可开关**：`CITY_ECON_MARKET.enable`（默认关 ⇒ 判据 A 不变）
【判据】
  A 关时：双路径 == `9018C2374EB44444` / `F2EABAC62D0B50AA`
  B 开时：① 工资指数对"劳动力短缺/景气"有正确符号的响应
         ② `avgIncome` 轨迹不再只由职级晋升驱动（与技术层趋势分离可辨认）
         ③ 投资随储蓄率变化（K 的轨迹可解释）
```

### 3.10 ⭐ ④ 的最小可施工骨架（**必须在 ③ 之后**）

```
【新增 2 个状态】
  city.rate    = 市场利率（由资金供求定：r = r0 + κ·(投资需求 − 储蓄供给)/GDP）
  city.credit  = 信贷存量（企业投资的外源融资比例）

【唯一接口】
  · 投资 I 的资金来源拆成：留存（自有）+ 信贷（借入）
  · 房贷利率从常数 `mortgageRate` 改为 `rate + 利差`（⚠ 存量合同不变 —— 见政府层口径需求）
【⚠ 不做（本轮）】准备金/货币乘数/证券/保险 —— 它们需要"银行体系"这一整层，先不建
【判据】开时：① 利率对储蓄率/投资需求有正确符号 ② 房贷新增额随利率下降而上升
```
