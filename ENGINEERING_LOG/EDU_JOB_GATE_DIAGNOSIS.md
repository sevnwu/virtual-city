### `JOBS[].edu` 的全部使用点（`grep "\.edu\b"` 49 命中里的关键一条）

```js
// :1635-1643  jobFit()  —— 全引擎唯一一处读 job.edu
function jobFit(job, abil, edu, arc) {
  let num = 0, den = 0;
  for (let d = 0; d < 6; d++) { num += job.ab[d] * abil[d]; den += job.ab[d]; }
  const abFit = (num / den) / 100;
  const eduFit = edu >= job.edu ? 1 - (edu - job.edu) * 0.03    // 学历过高：每档 −0.03
                                : 1 - (job.edu - edu) * 0.3;    // 学历不足：每档 −0.30
  const maxw = Math.max(job.w[0], job.w[1], job.w[2], job.w[3], job.w[4]) || 1;
  const pFit = job.w[arc] / maxw;
  return clamp(0.45 * abFit + 0.30 * clamp(eduFit, 0, 1.1) + 0.25 * pFit, 0, 1.2);
}                                 // ↑↑ 学历项权重只有 0.30，且下限被 clamp 到 0
```

**⇒ 数学后果**：学历项最多贡献 0.30。学历完全不足时该项 = 0，分数上限 =
`0.45 × 1.0 + 0.25 × 1.0 = 0.70`，而硬门槛 `jobFitMin = 0.42`（`:2109-2110`）⇒ **轻松通过。**

## 二、就业分配逻辑的筛选条件 —— 门槛只作用于「最高分」

```js
// :2089-2112  bestJobFor()  —— 全引擎唯一的岗位分配器
function bestJobFor(city, i, abil) {
  const a = abil || abilitiesOf(city, i);
  const edu = city.edu[i], arc = city.arche[i], id = city.id[i];
  let bj = -1, bs = -1;
  for (let j = 0; j < JOBS.length; j++) {
    if (edu < JOB_MIN_EDU[j]) continue;              // ★ 只排「学历不达【硬门槛】」的岗位
    const tgt = CIV.CITY_JOB_TARGET[j] || 0;         // 岗位需求压力
    const cur = (city.jobCount && city.jobCount[j]) || 0;
    const tot = Math.max(1, city.stats.employed || 0);
    let press = 1;
    if (tgt > 0 && tot > 100) {
      const want = tgt * tot;
      press = clamp(1 + (want - cur) / Math.max(1, want) * 0.9, 0.12, 3.0);   // ★ 0.12~3.0
    }
    const s = jobFit(JOBS[j], a, edu, arc) * (0.85 + hashOf(id, j * 13 + 5) * 0.3) * press;
    if (s > bs) { bs = s; bj = j; }                  // ★ 取【所有岗位的最大分】
  }
  const minFit = (CIV.CITY_VITAL && CIV.CITY_VITAL.jobFitMin) || 0.42;
  if (bs < minFit) return JOB_UNEMP;                 // ★ 门槛只作用于「最高分」
  return bj;
}
```

**筛选条件清单**（逐条）：

| # | 条件 | 位置 | 是否含学历 |
|---|---|---|---|
| 1 | `edu < JOB_MIN_EDU[j]` → 跳过 | `:2094` | ⭐ **含，但只在公务员上非 0** |
| 2 | 岗位需求压力 `press`（0.12~3.0） | `:2096-2103` | ❌ |
| 3 | `jobFit` 软分（学历权重 0.30） | `:1639` | 🟡 **软，无门槛力** |
| 4 | id 哈希抖动（0.85~1.15） | `:2104` | ❌ |
| 5 | **取最大分**（不按学历排序） | `:2105` | ❌ |
| 6 | `bs < 0.42` → 失业 | `:2109-2110` | ❌ |

### ⚠ 第二个独立机制：**需求压力可以把门槛冲掉**

`press`（最大 **3.0**）在**门槛判定之前**乘进分数，而 0.42 是拿**乘积**去比的：

> `raw jobFit = 0.15` × `press = 3.0` = **0.45 ≥ 0.42** ⇒ **录用**

⇒ 一个**长期缺人的岗位**（`cur ≈ 0` ⇒ `press → 3.0`）会把拟合度只有门槛 **1/3** 的人招进来。
这解释了为什么**越冷门的高学历岗位越容易出现学历错配**（医生目标份额仅 0.95%，抽样里常年 0~5 人 ⇒ 处于缺人态）。

### 其余分配路径**无新增绕过**（已逐条核对）

|---|---|---|
| 建城初次分配 | `:3308` 前 | ✅ |

| 跳槽 `hopTarget` | `:2046-2058`（门槛检查在 `:2051`） | ✅ |

| 迁入者 | `:5319-5324`（刻意走求职循环，不直接分配） | ✅ |
| 学历重抽后复核 `cityRepairCivilEdu` | `:2069-2087`（门槛检查在 `:2076`） | ✅ **但只复核 `JOB_MIN_EDU` ⇒ 只修公务员** |

⇒ **不存在"某条路径漏检学历"** —— 根因不是漏路径，是**门槛表本身只有 1 项非 0**。

### `abilitiesOf` 的个体抖动（这是把排序翻转过来的那一环）


## 三、「人岗匹配度」公式 —— **含学历，但只是 30% 权重的软项**

`json` 里页面上显示的「人岗匹配度 / 能力与岗位比较匹配」= `city.fit[i]`，
它由 `jobFit(JOBS[j], abilities, edu, arche)`（`:1796` / `:1840` / `:6833` / `:8658`）算得：

```
fit = 0.45 × 能力拟合 + 0.30 × 学历拟合 + 0.25 × 性格拟合
学历拟合 = edu ≥ job.edu ? 1 − 0.03×(超出档数)      （上限 1.1）
                        : 1 − 0.30×(不足档数)      （下限被 clamp 到 0）
```
⇒ ⇒ **档案上那个百分比【确实含学历】**（用户截图看到的 69% 里，学历项最多占 0.30）——
**而它只是分数的一部分，不构成"够不够格"的判定。**

同理收入里也有一项学历乘数，但很弱：
```js
// :3106
const eduMul = 0.80 + ed * 0.10;      // 初中 0.80 → 博士 1.30（只有 1.6 倍跨度）
```
