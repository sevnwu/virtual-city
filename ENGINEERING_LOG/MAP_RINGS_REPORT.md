## 二、几何方法（以及为什么它不是"拟合出来的"）

**数据源**（只读，不改）：`js/citysim.js`
```
L386   ringKm: 9.40,        // 【假设】每环的半径增量（公里）
L433   const DIST_POLAR = [ [0,180],[0,270], [1,200],... [4,190],[4,0] ];
```
`DIST_POLAR` = 16 个区的「**环号 0~4** × **方位角（0=正北 · 顺时针）**」，**与 `DISTRICTS` 同序**。

**一个必须先看出来的坑**：
> ⚠ `DIST_POLAR` 的顺序是 **`citysim.js` 的 `DISTRICTS` 顺序**，
> **不是 `shanghai.json` 的顺序**。两者**不一致**：
> `citysim`: 黄浦 静安 徐汇 长宁 普陀 虹口 杨浦 浦东 闵行 宝山 嘉定 松江 青浦 奉贤 金山 崇明
> `json`   : 黄浦 徐汇 长宁 静安 普陀 虹口 杨浦 闵行 宝山 嘉定 浦东 金山 松江 青浦 奉贤 崇明
> ⇒ 按 json 顺序去套 `DIST_POLAR` 会**整体错位**。本实现用 `citysim` 顺序。

**投影 → 屏幕上恰好是正圆**（这一步值得记）：
页面用的是等距圆柱（`x` 乘 `cosLat`、`y` 不乘）：
```
P(lon,lat) = [ W/2 + (lon-LON)·cosLat·s ,  H/2 + (LAT-lat)·s ]
```
把 `lon = LON₀ + R·sinθ/(111·cosLat)`、`lat = LAT₀ + R·cosθ/111` 代进去，
`cosLat` 正好约掉 ⇒
```
r_px = R_km / 111.0 × s          （s = s0 × zoom = 每度纬度的像素数）
```
⇒ 所以用 `ctx.arc()` 画正圆就**精确**等于"以原点为心、R 公里的测地圆"，不需要画椭圆、不需要采样折线。

## 七、可以顺手记的两条工程经验

```
⭐ ① scp 的 "ambiguous target" 解法：用【相对路径】
   之前用 `scp D:\...\x.js host:/tmp/` ⇒ Windows OpenSSH 把 `D:` 当成 host:path 的一部分 ⇒ 报 ambiguous target，
   且这个版本不支持 `-O`。解法不是 base64 绕行，而是【先 cd 进目录 · 用相对路径】：
       cd <本地目录>; scp -i KEY x.js host:/tmp/     ⇒ rc=0，sha256 逐字节对上。
   ⇒ 比 base64 中转简单得多，可作为首选。

⭐ ② 幂等检查必须检查【目标文件】，不能检查【自己的变量】
   本补丁第一版写成 `if (cnt(orig, tag) > 0) skip`，而 tag 是【我自己的标签名】
   （'cityapp:drawRings定义'）—— 那个字符串永远不会出现在文件里 ⇒ 永不跳过
   ⇒ 重跑一次就把补丁【重复插入】了（sha 变了、纯新增自证报 ❌ 才发现）。
   ⇒ 改成检查文件里的标记（'function drawRings()' / '/*5环*/'）后，重跑报"未改动" ✅。
   ⇒ 这与今天那"五种假通过"同族：**检查工具必须自证它在看正确的东西**。
```
