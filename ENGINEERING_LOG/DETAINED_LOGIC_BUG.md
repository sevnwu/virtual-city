# 羁押逻辑 bug —— 只读诊断（2026-10-07）

> **现象**（用户报）：市民 `VP369590`（梁书瑶 · 25 岁 · 女）第 1485 天因网络黑产被羁押候审，
> 而第 1486 天"开始交往"、第 1488/1489 天"骑车兜风（约会）"；

## 一、羁押状态位：`city.jailUntil[i]`

| 项 | 实测 |

| **门禁** | 全部检查点都带 **`LV2('crime')`**（crime 开关） |
| **设置（羁押候审）** | **`:5814-5815`** —— 重罪 `sev >= 3` 立案 ⇒ **`jailUntil[i] = trialDay`** |
| **设置（服刑）** | **`:5865-5866`** —— 判决 ⇒ **`jailUntil[i] = city.day + months * 30`** |
| **清除（缓刑）** | **`:5854-5855`** —— 判缓刑 ⇒ **当庭释放 ⇒ `= 0`** |
| **清除（刑满）** | **`:5880-5884`** —— 到期 ⇒ **`= 0`** |
| **持久化** | **`:6852`** —— 在快照字段清单里 ✓ |

## 二、🔴 约会逻辑**漏检了什么** —— 两处都漏

### ① `stepDates(city)`（**`:2721`**）—— **完全不排除在押者**

```
守卫（实测该函数内出现的判据）：关系存在 · 已婚者跳过 · loveBreakupP · hoursDateMul ·
   commuteDateMul · marryMinMeet · 季节/天气（dateOutdoorOK）
⇒ ⚠ 【没有 jailUntil】⇒ 在押者照样：
   · 开始交往（写 love 日志）· 每天掷骰子约会（写 date 日志）
   · 分手（写 breakup 日志）· 婚外情（同一函数内）
   · 并把结果写进 `city._dateToday`（`:2857-2858`）
⇒ ⇒ ⭐ **所以"第 1486 天开始交往 / 第 1488-1489 天约会"是【真的被模拟了】** ——
   **不只是显示问题** ✓✓（它会进"一生轨迹"，也会被统计进 `stats.dates`）
```

### ② `routineOverlayDate(city, i, st)`（**`:8395`**）—— **不检查在押 · 无条件追加**

```js
function routineOverlayDate(city, i, st) {
  const dt = city._dateToday ? city._dateToday.get(i) : null;
  if (!dt || !st || !st.length) return st;      // ← 唯一守卫就是"有没有约会"
  ...
  st.push({ h: h, act: `与恋人 ${pName} 在${place}（${dt.act || '约会'}）`, tag: 'date' });
  st.sort((x, y) => x.h - y.h);
  return st;
}
CIV.cityRoutineWithDate = function (city, i) {
  return routineOverlayDate(city, i, CIV.cityRoutine(city, i));
};
⇒ ⚠ **它【没有任何 `jailUntil` 判断】** ⇒ **把约会条目追加到【任何】日程上 · 包括监室日程** ❗
```

**⇒ ⇒ ⭐ 所以必须【两处都修】**：
```
· 只修 ①（stepDates）⇒ 不再产生新约会 ⇒ 但当天已写入 `_dateToday` 的仍会被追加（边界）
· 只修 ②（overlay）  ⇒ 日程干净了 ⇒ 但 `stepDates` **仍写 date/love 日志** ⇒
                        "一生轨迹"里仍有"被抓后在约会" ❗
```

## 三、日程为什么**同时**有"监室"和"约会"

### ⭐ 答案：日程是**两步拼接**，而**第一步在押者提前 `return`，第二步无条件追加** ⇒ **没有冲突裁决**

```
第一步  CIV.cityRoutine(city, i)                    ← 【正确的】

        :8202    P(6,  '起床 · 监室整理', 'home')
        :8213    P(8,  '监室教育学习（羁押候审）', 'work')
        :8215    P(14, '监室教育学习 · 放风（羁押候审）', 'work')
        :8216    P(18, '晚餐 · 监室活动', 'home')
        :8217    P(21, '点名 · 就寝', 'sleep')
        :8218    st.push({ h: 23.9, act: '羁押候审中 · … · 还剩 N 天' })
        :8221    return st;        ← ⭐【提前返回】· 正常日程（逛街/游戏/桌游）被跳过 ✓
        }
        ⇒ ⇒ ⭐ **"监室"是【替换】· 这一步的设计是对的** ✓

第二步  routineOverlayDate(city, i, st)             ← 🔴【漏检在押】
        :8396  dt = city._dateToday.get(i)
        :8404  st.push({ h, act: '与恋人 …（骑车兜风）', tag: 'date' })   ← ⚠ 追加
        :8405  st.sort(...)
        ⇒ ⇒ 🔴 **"约会"是【追加】· 而它没有和监室日程做任何冲突裁决** ✓✓

消费者  :8562  routine: routineOverlayDate(city, i, CIV.cityRoutine(city, i))
        ⇒ ⭐ **档案接口用的就是这个组合** ⇒ **所以监室 + 约会同时出现** ✓✓
```
