# 市民直达（问卷联动）：`?focus=<ID>` 自动打开档案

**日期**：2026-10-08 · **执行者**：子代理 · **状态**：✅ 已上线并验证（未目视浏览器）

---

## 一、需求

> 「仿真问卷平台跟虚拟城市链接起来了……可是现在查询起来蛮麻烦的，需要用户手动输入虚拟人的编号才能看到。
> 我现在让虚拟人系统去修改，看能不能不用手动输入，带虚拟人 ID 进去，就能看到虚拟人的资料。」

**目标**：URL 带市民编号 ⇒ 页面打开即**自动弹出该市民档案**，无需手动输入或点击。

---

## 二、⭐ 最终 URL 格式（问卷那边已在用，无需修改）

```
https://www.faceabc.com/city/sh.html?focus=VP509940
```

| 项 | 约定 |
|---|---|
| **主参数** | `focus` |
| **兼容别名** | `pid` · `cid` · `id` · `#focus=` · `#VP509940`（裸 hash） |
| **取值** | `VP509940`（带前缀，大小写不敏感）或 `509940`（纯数字）；容忍空白 / 逗号 / `+` / URL 编码 |
| **兜底** | 编号无法识别或不存在 ⇒ **显示友好提示**（列出正确格式），**不弹错、不显示别人** |

---

## 三、⭐ 关键发现：服务端只认纯数字，且无效 ID 会**随机返回一个人**

实测（同一请求连续 3 次）：

| 请求 | 第 1 次 | 第 2 次 | 第 3 次 | 结论 |
|---|---|---|---|---|
| `?id=945222` | 程婷 | 程婷 | 程婷 | ✅ 稳定 |
| `?id=509940` | 严梓萱 | 严梓萱 | 严梓萱 | ✅ 稳定 |
| `?id=VP945222` | 岳金鑫 | 任晨曦 | 雷楠鹏 | ❌ **每次不同** |

**根因**：`/city/api/citizen` **只解析纯数字**；拿不到有效 ID 时它**不报错**，
而是 **HTTP 200 随机返回一位市民**。

⇒ 所以「把 `VP945222` 填进输入框即可再次精确找到他/她」这句承诺，
**只在前端剥掉 `VP` 前缀后才成立**（`client.min.js` 与 `focus.js` 都会剥）。

⚠ **上游遗留 bug（未修 · 需另行决定）**：
`/api/citizen` 对无效 ID 应返回 **404 或明确错误**，而不是随机给一个人。
（修它要改 `city_server.js`；本次按指示**不动服务端**，只在前端做防御。）

---

## 四、实现：合并进 `js/focus.js`（单一机制）

发现**两套实现在打架**：

| | `js/focus.js`（另一任务的） | 我方 `client.min.js` 补丁 |
|---|---|---|
| 读参数 | `?focus=` / `#focus=` / `#VP…` | `?focus=`/`pid`/`cid`/`id` / `#pid=` |
| 动作 | 填 `#find-id` + **点 `#btn-find`** | 直接调内部函数 `St()` |
| **命中校验** | ❌ 无（坏 ID 会打开随机的人） | ✅ 有 |
| 稳健性 | ✅ **只用稳定 DOM id**，压缩包重构不受影响 | ⚠ 依赖压缩包内部函数名 |

**决策**：**合并进 `focus.js`** —— 保留它更稳的 DOM 接口设计，补上它缺的命中校验；
并把 `client.min.js` **完全还原**，避免双重触发。

**改动后 `focus.js`（5,704 B）**：
1. 命中校验：`GET api/citizen?id=<纯数字>` ⇒ **只有 `返回 id === 请求 id` 才点按钮**
2. 不命中 / 网络异常 / HTTP 非 200 ⇒ **显示"没找到这位市民"提示**（复用档案面板，
   关闭按钮走已暴露的 `globalThis.closePerson`）· **绝不显示随机的人**
3. 保留原有能力：`#focus=` / `#VP…` / 9 秒轮询等元素
4. 先把编号填进输入框（用户一眼看到"要查谁"），再异步校验

**线上脚本顺序**：`client.min.js` → **`focus.js?v=2`** → `board.min.js`

## 五、🔴 一次我造成的回退（已修复 · 教训）

```
服务器 sh.html 已被另一任务加了 <script src="js/focus.js?v=1"></script>（服务器 11,111 B）
而我的本地副本是过期的（11,071 B）⇒ 第一次部署用自己的副本覆盖 ⇒ 把那一行删掉了
```
**修复**：改用**服务器实际版本**为基准重建本地（不再用我的过期副本），并把 `v=1` → `v=2`。

⭐ **教训**：**部署前必须核对"线上原件 sha256"** —— 本地工作副本可能过期；
「我以为的本地 == 线上」正是此前栽过的那条。

## 六、验证

| 判据 | 结果 |
|---|---|
| **真跑一遍**（DOM 桩 + vm，抽取**线上实际文件**执行） | **14/14 通过** |
| 覆盖 | `VP509940` / 纯数字 / 小写 / `#focus=` / `#VP509940` / `pid` / `cid` / `id` / 多参数 / 空值 / 无参 / 非数字⇒提示 / 不存在⇒提示 |
| **异常分支** | 网络异常 ⇒ 提示且不点击 ✅ · HTTP 非 200 ⇒ 提示且不点击 ✅ |
| **变异自证**（证明测试能失败） | **3/3 变异全被抓到** ✅ |
| 部署 | **三方 sha256 逐字节一致（3/3）** · 并断言"捕获行数必须=3" |
| 线上 HTTP | `sh.html` · `sh.html?focus=VP509940` · `focus.js?v=2` · `client.min.js` · `api/citizen?id=509940` · `versions.html` · `/city/` ⇒ **全 200** |
| 关键字核对（UTF-8 正确解码） | 线上含 `focus.js?v=2` · 已无 `v=1` · 已无我引入的旧串 `…2130` · 线上 `focus.js` 与本地逐字节一致 |
| 依赖核对 | `#find-id` · `#btn-find` · `#person` · `#btn-tip` · `#find-tip` 各 1 处 · `closePerson` 已暴露 |

⚠ **过程中抓到两个"我的测试错"**（都不是代码错）：
1. 桩写错 —— 对任何纯数字都回请求的 id（真实语义是"不存在则随机"）
2. 抽取偏移 `+18` 实际应为 `+16`（`'/*FOCUSURL:END*/'.length === 16`），多抓两个字符

⇒ ⭐ 与今日累积的**"检查工具必须自证"**同族。
