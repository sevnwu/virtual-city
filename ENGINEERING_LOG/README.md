## 二、诊断链（按时间顺序）

这一版的关键是**一条被连续四次推翻的诊断链**。每一步的结论，都被下一步的实测否掉：

```
① 起点：「财政约束消失」—— 城市"钱花不完"
      ↓
② 诊断 1：建设侧与维护侧用了【两套价格】，差 17~72 倍
      ⇒ 修法：REALCOST（建设侧改用真实资产值）
      📄 GOV_FISCAL_CONSTRAINT_FIX_REPORT.md · TAX_MAGNITUDE_AUDIT.md
      ↓
③ 诊断 2：「REALCOST 修过头」—— 2,500 人城市 291~376 年才建得起一次
      ⇒ 修法：给 green 加最小人口门槛
      📄 GREEN_MINPOP_DERIVATION.md · GREEN_GATE_SWITCH_REPORT.md
      ↓
④ 诊断 3：根子在 unitPhysical —— "1 级 = 20 km 地铁 / 500 公顷绿地"是
      【上海尺度】，被施加到每一个城市
      ⇒ 修法：unitPhysical 随人口缩放
      📄 GOV_INFRA_SCALING_DIAGNOSIS.md · GOV_UNIT_SCALE_REPORT.md
      ↓
⑤ ⭐ 诊断 4（纯算术推翻 ③④ 的判据）：
      "人均缩放"【不会改变】"建一次要多久" —— 因为资产和税收都 ∝ 人口
      ⇒ ⭐ 而真实对照（上海公园绿地全存量 ÷ 年财政收入 = 0.17 年）说明：
        "财政不 bind" 本来【就符合真实世界】，不是 bug
      ⇒ ⭐ 真正的偏差只有一条："2,500 人城市被要求 500 公顷绿地"（地理上荒谬）
      📄 POP_SCALE_REPORT.md
```

**⇒ ⭐ 结论**：这一版**不追求让财政变紧张**。理由是"财政不 bind"与真实世界一致
（基建投资占财政收入的比例本来就不高）；若人为制造紧张，反而会把结论弄反。

## 四、⚠️ 方法论：**三次「假通过」**

这一节是本目录**最该被读**的部分。

三次都是**检查工具本身出错，而它报告"通过"**。三次形态不同，但属于同一族：

| # | 形态 | 实例 | 假通过的样子 |
|---|---|---|---|
| **①** | **检查根本没执行** | `_selfcheck.cjs` 的 C2（在押期间禁约会）：`jailUntil` 字段全缺失 ⇒ 该分支从未进入 | 四项**全报「✅ 0 例」** |
| **②** | **分支根本没跑到** | 探针轮转测试：用例只造出 **20.39 MiB** < **20.97 MiB** 阈值 ⇒ 轮转分支未执行 | 报「✅ 通过」 |
| **③** | **读了自己** | 核对脚本用了 `process.argv[1]`（= 脚本路径）而非 `argv[2]` ⇒ 读的是脚本自身，而要检查的字符串就写在脚本源码里 | 关键表述**全报「✅ 在」** |

### ⇒ 通则：检查工具必须**自证三件事**

```
① 它【执行了】      —— 分支真的跑到（不是"没数据所以通过"）
② 它读的是【目标】  —— 对象正确（打印"实际读的路径 + 字节数"即可立刻发现 25,374 vs 1,125）
③ 它【能报出该报的错】—— 拿一个已知有问题的样本喂它，看它会不会报错
```

**推论**：**"未执行"必须与"通过"分开报告**（本项目用退出码 `3 = 未执行` 区分）。
一个**永远报「✅ 通过」**的检查器，**比没有检查器更危险** —— 因为它给的是虚假的安全感。

### 同族的其他坑（本目录各报告中均有记录）

- **「两臂相同」有四个原因**（开关没开 / 机制中立 / 无预算可花 / 账本无反馈）⇒ 不能仅凭"两臂相同"断言机制无效；
- **「钱太多」也能让差异不可见** —— 建造受需求触发而非预算限制时，改成本不产生可观测差异；
- **「开关进了 env」≠「开关进了引擎」** —— 生产环境的启动器可能**根本没有读 env 的路径**（v1.3.0 的 11 个开关里只有 4 个能被 env 设置）；
- **「没有日志」≠「没生效」**，且反向也成立：**「有开关」≠「有行为」**；
- **符号读错**（把 `- (p.green - 1)` 读成 `(p.green - 1)`）会让结论**方向反**，而**逐字符核实比跑仿真更直接**。
