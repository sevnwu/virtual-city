## 三、⭐ 户口分层：一次"我编了一个不存在的行政层级"的自我纠正

**问题（由外部质疑引出）**：
```
v1.5.0 写「城市 / 县城 / 农村」三档，其中「城市 vs 县城」拆分比例 72 / 28。
外部质疑：上海现在没有"县"了（都是区 / 镇），这 24.32% 的"县城"在参照系里代表什么？
```

**查证结果**：
```
· 上海崇明 2016 年撤县设区 ⇒ 全市 16 个区，**无县级建制**（人民日报 2016-08-09：
  全国四个直辖市已有三个进入"无县时代"）
· 更要紧的是：72/28 这个拆分比例**没有任何官方来源** ——
  它是把两条**互相正交**的统计轴混算了：
    · 城镇化率 89.85%          属于【户口性质：非农 / 农业】
    · 户籍常住 / 外来常住      属于【户口登记地：本地 / 外地】
  两条轴的数字相减去凑一个"中档"，算出来的数**没有现实对应**
```

**改法：上海诚实地只有两档（全部官方单列）**
```
上海 2024 统计公报：常住 2,480.26 万 = 户籍常住 1,496.77 万 + 外来常住 983.49 万
  ⇒ 本地户籍 60.3473% / 外来常住 39.6527%（和 = 100% ⇒ 对常住人口的**完备二分**）

⚠ 为什么不设「农村」档：官方**未单列**上海农业户口人数（统计年鉴无此项）。
  若强行做三档，就必须假设"全部 983.49 万外来常住都是非农"，而该假设无官方依据
  ⇒ **宁缺勿猜**。
```

**⭐ 关键设计：分层定义改为【由各城声明】，引擎不再假设**
```
① 有县城市  mode='city-districts' ⇒ 城市户口 / 县城户口 / 农村户口（本城行政区划口径）
② 无县城市  mode='city-no-county' ⇒ 本地户籍 / 外来常住 / 农村户口（官方单列口径）
⇒ 引擎通用消费；未声明则回落默认；老数据集不受影响
```
**可扩展性已实测**（不是空口）：
```
有县城市配置（示例 45/20/35）⇒ 实测 44.80 / 20.24 / 34.96 · 标签"县城户口" ✓
无县城市配置（示例 70/22/8） ⇒ 实测 69.86 / 22.00 / 8.14  · 标签"外来常住" ✓
```

**⚠ 户口是【纯标签】**：只用于调研问卷分层抽调，不做任何行为影响，且由 `(seed, id)`
哈希派生、**不消耗主随机流** ⇒ 判据 A（`9018C2374EB44444`）保持，建城与仿真轨迹逐字节不变。

## 四、犯罪成因：方向来自文献，倍数是模型假设

```
上海统计局口径释义（外来常住 = 离开户口登记地半年以上的外省人口）
文献方向锚：章元等《城乡收入差距、民工失业与中国犯罪率的上升》（《经济研究》2011）
  结论：**失业**是主因（城镇登记失业率与犯罪率 r = 0.82）· 城乡收入差距**不显著**
  机制：**脆弱性**（缺乏最低生活保障与社会保险、社会网络在农村）
```

**实现**：个体风险 = 基准 × 因子（负债 / 破产 / 家庭月供缺口 · 失业 × 脆弱性（农村户口、迁入者）·
健康冲击 · 性格与情绪 · 职位便利 · 关系冲突），并按人口**均值归一**。

**实测**：
```
· 开关关：2,546 人的风险恒为 1（逐字节不变）
· 开关开：0.32 ~ 2.54 · **均值 1.0013**
· 失业 ×2.39 · 失业且农村户口比城市户口高 26.9% · 负债 10 万 ×2.36 · 职级 ≥5 ⇒ 涉案额 ×3.25
```

⚠ **诚实标注（已写进接口与文档）**：除"失业 × 脆弱性"有文献支持**方向**外，
**所有倍数均为模型假设**。中国没有"负债 10 万使犯罪率上升 X%"这类权威公开数据 ⇒
**不得**把倍数当实测系数引用。

## 五、住房：修掉三个真缺陷，但剩余缺口**修不好**（已立为 LIMITATIONS L-13）

| 缺陷 | 现象 | 修后 |
|---|---|---|
| 断供判据缺一项 | 不检查「是否真的欠着贷款」⇒ **无月供的自有房主**也被以"因无力偿还按揭"处置房产（触发 518 次，首次在第 1 天） | 按户有房率 y12 **28.0% → 37.5%（+9.49pp）** · 触发 **518 → 190** |
| 存量房主从未标定 | 线上一直走快照恢复，而建城标定只在第 0 天执行 ⇒ 有房率仅 **2.54%**（14,506 房主里 14,448 带贷款） | 线上 **2.54% → 47%** |
| 房产没有继承 | 遗产只分金融财富、**不分房产** ⇒ 房子随人口更替单向消失 | 按法定顺序（配偶 → 子女 → 父母）转移**产权与剩余房贷** |

**⭐ 为什么剩余缺口修不好 —— 拆门槛实验（这是本轮最有价值的负面结果）**：
```
月供比 60%→45%（收紧）  +1.43pp      月供比 60%→70%（放松）  −1.18pp
首付 25%→20%            +0.46pp      月供比 60%→100%         −6.9pp
首付 25%→10%            +2.5pp       房价 −30% / −47%        −0.6 / −0.7pp
⇒ **两道门几乎全拆**：成交 **×2.6**，但有房率 **−2.7pp**
⇒ **放宽信贷总是有害**；**拆掉全部可负担性门槛后有房率依然下降**
⇒ 说明它由**存量年龄结构**决定，而非收入 / 房价 / 政策
```

## 六、政府账本：一个"用户点了没反应"的真根因

```
现象：用户问「我点建地铁，地铁数会增加吗？」⇒ 实测**不会**，且界面没有任何提示
根因：① `intervene()` 先撞 `CITY_GOV_ENABLE && !canAfford(...)` ⇒ 直接 return false，什么都不改
      ② 而 `/api/intervene` **丢弃了返回值**、无条件回 `{ok:true}` ⇒ 前端无法区分"成功"与"被预算拒绝"
      ③ 更深一层：**快照不保存政府账本** ⇒ 每次服务重启国库归零
         ⇒ 地铁单级造价约 **24 亿元**，而国库反复归零 ⇒ **永远攒不够**
修：账本写入快照并在恢复时读回；`/api/intervene` 如实回报 ok / applied / reason / need / treasury
实测：跨月界后快照 meta 含 gov · treasury **16.44 亿元**完整保留；现线上已结账 **31 个月**、国库 **514.9 亿元**
```

## 七、⭐ 本轮沉淀的方法论（面向复用者）

```
① **同一个"漏一处"的坑，本会话踩了三次** ⇒ 最终定案：
   凡是"多套载体共享一个值"（版本号 / 行数 / 缓存串 / 配置）⇒ **必须由脚本生成 + 断言门禁**，
   不得手写。已落地 `tools/set_version.cjs`：一键设版本 + 4 项一致性断言（失败即退出码 1）。
② **长跑的子进程不能留在调用方的进程树/job 里** —— 同一根因踩了三次：
   `Start-Process` / `cmd start /b` / `schtasks`（本机被沙箱拒绝）
   ⇒ 定案 `spawn({detached:true, stdio:['ignore',fd,fd]}) + unref()`。
③ **备份不得落在 webroot 内** —— `.bak` 后缀不会匹配按扩展名写的缓存规则，
   实测曾把旧包公开挂在网上（HTTP 200）⇒ 备份一律放 webroot 之外。
④ **"日志里没有" ≠ "没有发生"** —— 应用日志被重定向到文件而不在 journald 里，
   我曾据此误判"记账从未执行"并做了 3 次无谓部署。
⑤ **快照续跑不能用于长跑分段** —— 硬验收实测「从快照起跑 ≠ 直接跑」
   （harness 侧状态：灵魂 / 转世 / 关系边 / TRAIN 不在城市快照里）。
⑥ **M4 内存判据的度量方式有缺陷** —— 它在年末快照上量相邻差，而 RSS 是**周期信号**
   ⇒ 必然年年误报。39 年读数实测为 GC 摆动形态（正增量 22 年 / 负增量 16 年），
   但**证据不足以区分"极慢泄漏"与"长周期摆动"** ⇒ 不应写成"已通过"或"已失败"。
```

## 八、🔴 一次协作事故：我**静默删掉了一个别人加的端点**

**如实记录**（这不是光荣的记录，但正是本目录存在的意义）：

```
事实：
  平台侧会话在 city_server.js 里加了 `/api/member`（常驻成员「吴昊」的登记接口），
  并自带了来历注释。我在同一时段重写该文件（v1.5.0/v1.5.1 发布）时，
  **以我的历史副本为基线** ⇒ 该分支被**静默覆盖**。
  症状：**不报错、不崩溃，只是少一个端点** —— 直到平台侧做收尾探测才发现。
  处置：平台侧按备份 city_server.js.preWuhao_20261011160508 恢复并验证（2026-10-14）。

根因（三条，缺一不可）：
  ① **两个会话在同一代码库上工作，按"文件"而非"话题"划分归属** ⇒ 撞车不可避免
  ② 我把"我的本地副本"当成了基线 —— 而它**早于**对方的改动
  ③ 我**没有"改完立刻探测"** —— 不探测就会一直以为它活着

⭐ 由此定的协作纪律（已写入双方约定）：
  · 重建共享文件时**必须以【线上文件】为基线**，不得用任何本地历史副本覆盖
  · 改完**立刻探测一次自己的成果还在不在**（本例：`curl /api/member` 期望 200）
  · 改共享文件前看 mtime + 建带时间戳备份（`*.preXxx_<时间>`）
  · 不在对方正在动的文件上长时间工作；确需动，先写一行"我要动 X 到什么时候"
```

⚠ **这条同时是一般性教训**（适用于任何多人/多会话协作的代码库）：
> **"删掉一个分支不会报错"是最危险的失败模式** —— 它没有编译错误、没有运行时异常、
> 没有日志，只有**一个功能悄悄消失**。凡是"可静默丢失"的东西，都必须有**主动探测**。

## 十、🔴 又一个"静默丢失"类 bug：`zkTier` —— 以及**审计工具的枚举口径缺陷**

> 由仿真问卷平台侧（运行者）的实测清单引出。**这条的价值不在 bug 本身，而在
> "检查工具的枚举口径本身必须被质疑"**。

### 事实

```
citysim.js:9291   if (!city.zkTier) city.zkTier = [];     ← 按人数组
citysim.js:9303   city.zkTier[i] = t;                      ← 按下标赋值（15 岁中考档位 0~3）
❌ 不在 compact() 的两个重排列表   ❌ 不在快照 ARR
⇒ compact() 每 30 天移除死者并缩短 age，而 zkTier 不缩
⇒ ① 下标整体错位（中考档位会算到别人头上）② 数组永不收缩（内存只涨不降）
```

这是同类事故的**第三次**（前两次：`civic` 7 个数组实测差 686；`_payHelp` +1,859 / `_familyGap` +645）。

### ⭐ 为什么它能躲过审计这么久（**这是本条最重要的部分**）

```
tools/_audit_compact_lists.cjs 的【旧枚举口径】：
    把【快照 ARR】当作"按人数组的权威清单"，
    然后只检查  ARR ⊆ compact 列表
⇒ 任何**既不在 ARR、也不在 compact** 的按人数组，
  **根本不在检查范围内** ⇒ 工具报 "✅ 全部都在列表里"，而实际上有缺口。

⇒ 这是"假通过"的一种，与仓里既有的八种同源：
   **一个只检查 A⊆B 的工具，无法发现"既不在 A 也不在 B"的东西。**
   （它无法自证自己的枚举是完备的 —— 而"完备性"恰恰是这类审计的全部价值。）
```

### 修法

```
引擎      ：compact 第二个重排列表 补 'zkTier'
宿主      ：ARR 追加 ['zkTier','U8']（**末尾** ⇒ 旧快照按"缺字段补 0"读，语义正确）
离线 harness：ARR 同样追加（并把此前缺的 6 项一并补齐，见下）
审计工具  ：改为【从引擎源码枚举按人数组】（四种写法取并集），再分别对
            compact 两个列表 与 **两份 ARR** 做差集；并新增【两份 ARR 一致性检查】
```

### 顺带查出：两份 ARR 曾经不一致

```
宿主 city_server.js 与离线 tools/city_snapshot.cjs 是**两份手工副本**。
实测曾有 6 项只在宿主、离线没有：
  famFlag · bornDay · diedDay · marryDay · unmarryDay · lastSpouseId
⇒ 离线 harness 写出的快照缺这 6 项 ⇒ 离线恢复后它们全部归零。
已补齐并让两份完全一致（各 63 项）；审计工具现在每次都会检查这一点。
```

### 部署实测（旧快照兼容性）

```
[resume] 旧快照缺少字段（将用默认值补齐）：zkTier
⇒ 正是"追加在末尾 + 缺字段补 0"的设计生效（0 = 未参加过中考，语义正确）
```

### ⚠ 一般性教训（可迁移）

> 任何一个"按清单检查完整性"的工具，都**必须把清单本身也当作被检查对象**。

## 十一、⭐ 教育口径：**学历在 18 岁一次性锁定** ⇒ 年龄×学历不得用于代际结论

> 由平台侧的 P0-1 / P1-1 引出。**这是本轮最有价值的一条"负面结果"** ——
> 我们**没有**去调参掩盖它，而是把它测清楚并声明出来。

### 实测（线上真值 · 12,000 次无偏采样）

方法：`/api/citizen?id=<不存在的 ID>` 会**静默返回随机一个人**
⇒ 等价于全人口随机抽样（**这是线上真值，不是复算**）。

```
年龄组    | 初中及以下 高中/中专  大专    本科    硕士   博士 |  大专+
22-24    |  51.0%   16.2%  32.9%   0.0%   0.0%  0.0% | 32.86%
25-26    |  46.4%   21.9%  30.5%   1.3%   0.0%  0.0% | 31.79%
27-29    |  50.9%   22.9%  25.9%   0.3%   0.0%  0.0% | 26.15%
30-34    |  44.1%   19.6%  34.3%   1.7%   0.3%  0.0% | 36.30%
35-44    |  44.9%   21.0%  15.7%  13.9%   4.0%  0.5% | 34.11%   ← 本科+ 突然出现
45-59    |  48.4%   19.8%  12.9%  14.9%   3.4%  0.5% | 31.78%
60-70    |  46.8%   20.7%  15.0%  13.8%   3.5%  0.2% | 32.50%
70+      |  46.1%   20.8%  14.7%  14.8%   3.1%  0.5% | 33.13%
18-70合计 |  46.9%   20.3%  18.6%  11.1%   2.8%  0.3% | 32.82%
```

**两个结论**：
```
① 总量口径是对的：四个年龄组的"大专+"都在 31~36%，18-70 合计 32.8%（接近七普 33.12%）
② 但结构是一条【硬台阶】：本科+ 在 35 岁以下 ≈ 0~2%，35 岁以上 ≈ 18~19%
```

### 机制（可逐行核对）

```
引擎在【18 岁】那年把学历一次性定稿：
    citysim.js:9306-9308   a===18 ⇒ city.edu[i] = educationOf(city, i)
    且 schooled 位掩码保证【只跑一次】⇒ 此后 18~终身**永不重算**
    （22 岁的支路只写日志，不改 edu）
⇒ 学历锁在"18 岁那一刻的抽样分布"上
⇒ 任何改变"18 岁当下解算结果"的引擎改动（截断规则、EDU_BY_DIST 修正、甚至一次 bug 修复）
   都只影响**此后**到 18 岁的人，而**已过 18 岁的人永久冻结在旧口径** ⇒ 跨队列断层
```

**⚠ 证据强度（不含糊）**：
```
✅ 确证：机制在代码里可逐行核对（9306-9308 的"只跑一次"锁）
✅ 确证：线上真值台阶存在，且位置在 35 岁
⚠ 未能确证：**为什么台阶落在 35 岁而不是别处** ——
   那取决于历史上哪一天改过哪一处（本仓 git 历史只到 v1.5.0，查不到）
⇒ 因此本文只宣称"学历一次性锁定 + 台阶存在"，不宣称"根因已完全确定"
```

### ⭐ 一条对所有人的直接告诫

```
同一引擎 + 同一开关，从零建城跑 8 年 ⇒ 25-29 岁的本科+ ≈ 21%
线上同年龄段实测                        ⇒ 本科+ = 0.3%     （差 20 倍以上）
⇒ **线上城市的学历结构携带历史状态，不是当前引擎的稳态输出**
⇒ 任何"用离线复刻推断线上学历"的做法都会错
```

### 处置：**声明而不是调参**

```
· 引擎新增机器可读口径：/api/state → census.caliber
    edu.level = 'stock-steady-state' · lockedAtAge = 18 · lockOnce = true
    edu.measured = '35 岁以下 本科+ ≈ 0~2% · 35 岁以上 ≈ 18~19%（线上 12,000 次无偏采样）'
    inSchool.authoritative = 'CIV.cityEduInSchool(age, edu, schooled)'
· 措辞要点：年龄组间的学历差异主要反映【模拟历史】，不是现实队列差异
  ⇒ **不得用于任何代际/队列结论**
· 为什么不调参去"抹平"台阶：那等于用一个假设替换另一个假设，
  而且会掩盖"学历一次性锁定"这一真实结构 —— 见 LIMITATIONS 的使用规则
```

### 同时落地：在读状态的**权威口径**（平台侧 P0-1）

```
引擎新增 CIV.cityEduInSchool(age, edu, schooled)（纯函数 · 不吃 rng · 不写字段）

口径：18~21 ⇒ '本科在读' · 22~24 且 edu≥2 ⇒ '硕士在读'（若 schooled 有 bit3 而 edu<4 则判非在读）
⚠ 为什么"按学制推导"而不是读一个"在读标志数组"：
  city.schooled 只在【精确整岁那一天】写入 ⇒ 建城存量人口、迁入者、

```

## 十二、⚠ 又一条自己踩的坑：**"改成委托"≠"两条口径就一致了"**

> 部署之后按"**改完立刻探测**"复验，抓出**我自己引入**的 bug。
> 这条与第十/十一节并列，是同一批纪律的第三个案例。

### 症状（探测才看得见）

```
用无效 ID 触发随机返回，采 780 条，逐条比对两个字段：
    eduGrad ≠ eduInSchool 的条数 = 9
      age=24.5  edu=2  eduGrad='硕士在读'  eduInSchool=''
```

⚠ **注意：如果只看"`/api/state` 返回 200"和"两个字段都存在"，会以为已经修好了。**
差异只在**少数样本**上显形（9/780 ≈ 1.2%）—— 只看健康检查必然漏掉。

### 根因

```
函数体确实委托了：  CIV.cityEduGrad = (age, edu, schooled) => CIV.cityEduInSchool(age, edu, schooled);
但调用点的【实参语义】没对齐：
    宿主原文：cityEduGrad(city.age[i], city.edu[i], city.eduFinal[i])
                                                        ^^^^^^^^^^^^^^^^
               第三参传的是 **eduFinal（最终学历）**
    而新定义的第三参是 **schooled（位掩码）**
⇒ eduFinal 的取值被当成位掩码去判 `done & 8`
⇒ 那条排除判据随机生效/失效 ⇒ 两条口径在实际返回上不一致
```

### 教训（可迁移，且与仓里既有纪律同源）

> **"把实现改成委托"只统一了【函数体】，没有统一【实参】。**
> 只要签名相同、语义不同，编译/语法检查都不会报错，而结果会**只在部分输入上与预期不同** ——
> 这是最难发现的一类不一致：**它不会崩，只会偶尔给出不同的答案。**

⇒ 因此"委托化"的正确做法是三步，缺一不可：
```
① 统一函数体（委托）
② **逐字核对实参语义**（尤其"同类型不同含义"的参数：位掩码 vs 等级 vs 计数）
③ 写一个**逐条比对两条口径**的探测（本例：900 条样本，`eduGrad == eduInSchool` 必须 0 条不一致）
```

### 修法与复验

```
修：把 schooled 的取值提到 eduGrad 之前，两者共用同一个值
复验：900 条样本 ⇒ eduGrad ≠ eduInSchool = **0 条** ✅
（修复脚本自带四项自证：schooled 赋值只出现 1 次 · 旧的错误实参出现 0 次 ·
  schooled 在 eduGrad 之前 · 语法通过）
```

⚠ **这条也顺带说明另一件事**：本轮三次修改（zkTier / eduInSchool / census.caliber）之后，
每次我都重跑了**判据 A + 7 个回归套件**；而**这个 bug 是判据 A 与回归套件都抓不到的** ——
因为它是**展示层字段的口径不一致**，不进 `demog.csv`、不参与仿真。
⇒ **判据 A 保护的是"仿真行为"，保护不了"接口语义"** ⇒ 接口层的变更必须另有逐条比对的探测。
