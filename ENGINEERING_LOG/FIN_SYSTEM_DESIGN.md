# 金融体系设计（④ · 银行最小版）

**日期**：2026-10-10 · **状态**：**设计（未实施）** · **前置**：`FUTURE_SYSTEMS_GAP_MAP.md` §4（④ 的设计与参数清单）
**依赖**：③ 经济系统（已上线 v1.4.1）—— 特别是**厂商资金流**给出的"融资缺口"信号
**纪律**：显式开关且**默认关** · 关闭时判据 A 逐字节不变 · 参数逐项标三态

---

## 一、⭐ 先回答"谁存款、谁贷款"（否则做出来的东西没有主体）

```
现状（③ 上线后）：
  住户：财富 `city.wealth[i]` 通过 `assetPlMean` 获得收益 —— 但**收益来自哪**？代码里没有对手方。
  企业：投资 = invRate × Y 是一笔**纯支出**；留存是内部资金；**缺口**（负值=净储蓄）无人承接。
  ⇒ ⭐ **中间没有中介** —— 这正是"金融体系"要补的那个位置。

最小金融体系的主体（**只加一个部门**）：
  🏦 **银行部门**（单一合成主体 · 不做逐家银行）：
      负债 = 住户存款 D          （住户的财富以"存款"形式持有）
      资产 = 企业贷款 L_f + 房贷 L_h
      权益 = 资产 − 负债（净值）
  ⭐ 关键：**住户财富不再是悬空的资产池 ⇒ 它就是银行的存款负债**
     （这一步就把"资产收益从哪来"变成有来源的：**借款人付的利息**）
```

## 二、⭐ 利率：基准 + 利差（用户建议的接法）

```
用户的指示："mortgageRate 改为 基准利率 + 利差"

  基准利率  r_base  ← 由**货币政策规则**给定（不是市场出清）：
      · 先做**常数**（可标定）；后续可接泰勒规则的简化版：r = r* + φ(π − π*) + ψ·(产出缺口)
      ⚠ 目前**未找到**中国货币政策的权威可引用反应函数参数 ⇒ 先做常数 + 敏感度
  利差  spread = 风险溢价 + 期限溢价 + 银行成本
      · 房贷：spread_h（**模型假设**；可用"5 年期以上 LPR 与 5 年期国债利差"标定，待查）
      · 企业贷：spread_f（**模型假设**）
  ⇒ 实际利率：房贷 r_h = r_base + spread_h · 企业贷 r_f = r_base + spread_f

⚠ 与既有 `assetPlMean = 3%` 的关系（**必须处理，否则又是重复计数**）：
  · `assetPlMean` 是**资产年化期望真实收益**（引擎既有 · 住户财富的收益）
  · 金融体系上线后，住户财富的收益**应当来自存款利率** ⇒ `assetPlMean` **由 r_D 取代**
    （r_D = 存款利率 = r_base − 存款利差）
  ⚠ 这是一处**替换**，不是叠加 ⇒ 必须做开关 + 判据 A + 首次启用时重记基线
```

## 三、信用创造：**贷款创造存款**（银行系统的核心机制）

```
⭐ 关键机制（这是"银行"区别于"把存款转借出去"的地方）：
  银行发放贷款时**同时创造存款**：
      放贷 L：资产 +L（贷款）· 负债 +L（借款人的存款）
      借款人支用：存款转给交易对手（本模型里主要是"企业投资"与"购房"）
  ⇒ 银行体系的**存款总量由贷款决定**，不是先有存款再放贷。

⚠ 对本引擎的处置（**最小实现**）：
  · 不做"逐笔贷款"（O(N²) 且无标定锚）
  · 做**总量口径**：`city.fin.L_f`（企业贷余额）· `city.fin.L_h`（房贷余额）· `city.fin.D`（存款）
  · 房贷：**既有 mortgage 已逐户记账** ⇒ 只把它的**利率**改为 `r_base + spread_h`
    （当前 `mortgageRate` 6 处硬编码 ⇒ 改为读金融层）
  · 企业贷：只为**融资缺口**（缺口 > 0 时）提供资金；缺口 ≤ 0 时企业**净偿还**
```

## 四、货币与准备金（**最小 · 不做货币乘数的复杂版**）

```
准备金率 ρ（模型假设；中国法定准备金率约 7~11%，但**对模型的意义有限**）：
   · 最小实现**不做准备金约束**（因为本模型没有"央行—商业银行"两层）
   · 改为一条**信贷供给上限**：银行放贷不超过其**存款 × 杠杆上限 κ**
       κ = 10（**模型假设**；对应权益/资产 = 10%，接近《巴塞尔协议III》核心一级资本要求）
     ⇒ 这是**信贷配给**的来源：当贷款/存款接近 κ 时，新增贷款被**配给**（部分拒绝）
```

## 五、状态量与接口（沿用既有风格：显式、可自证、默认关）

| 字段 | 含义 | 单位 |
|---|---|---|
| `city.fin.D` | 存款总额（= 住户财富中以存款形式持有的部分）| 元 |
| `city.fin.L_f` | 企业贷款余额 | 元 |
| `city.fin.L_h` | 房贷余额（可由既有 mortgage 汇总）| 元 |
| `city.fin.equity` | 银行净值 = 资产 − 负债 | 元 |
| `city.fin.rBase` | 基准利率（年化）| — |
| `city.fin.spreadH` / `spreadF` | 房贷/企业贷利差 | — |
| `city.fin.rationed` | 本期被配给（拒绝）的贷款额 | 元 |

**接口**：
```
CIV.cityFinOn()                 开关
CIV.cityFinStep(city)           月度步（利息计提 + 缺口融资 + 配给）
CIV.cityFinRateOf(kind)         取利率（房贷/企业贷）· 既有 mortgage 改读它
CIV.CITY_FIN_INFO(city)         口径自证：资产负债表 + 缺口覆盖率 + 配给率
```

## 六、判据（实施前定死）

| # | 判据 | 通过条件 |
|---|---|---|
| **F-A** | 开关关闭 | 判据 A 双路径**逐字节不变** |
| **F-B** | 资产负债表恒等 | `资产 − 负债 − 权益 = 0`（断言 · 每期自证）|
| **F-C** | 房贷利率替换 | 开关开时 `mortgageRate` 全部改为 `r_base + spread_h`；**关时逐字节不变** |
| **F-D** | 缺口融资 | 企业融资缺口 > 0 时，`L_f` 增加 ≈ 缺口；覆盖率 = 融资额/缺口 ∈ [0,1] |
| **F-E** | 信贷配给 | `L_f/D` 达 κ 时，新增贷款被配给（`rationed > 0`）且投资相应受限 |
| **F-F** | 无重复计息 | ⭐ 静态断言：**住户财富的收益只有一处**（要么 `assetPlMean`，要么 `r_D`，不可并存）|
| **F-G** | 利息有对手方 | 借款人付息 = 存款人收息 + 银行净息差（三角恒等 · 断言）|

## 七、⚠ 明确**不做**的（避免范围失控）

```
❌ 逐笔贷款 / 逐家银行（O(N²)、无标定锚）
❌ 货币乘数、央行—商行两层、公开市场操作
❌ 影子银行、理财产品、直接融资（股市/债市）
❌ 汇率与跨境资本流动（无城市级数据锚）
❌ LPR 报价机制（需要 18 家报价行 —— 城市级仿真无此主体）
```
