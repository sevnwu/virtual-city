## 一、设计（两个决定 + 为什么）

### 1.1 同一快照 + 换 `meta.seed`（不是"各种子各自跑到该年再快照"）

```
每份快照 = `iv_y2.bin`（第 730 天 · 2,616 人）的副本，**只改 `meta.seed`**，数组块逐字节复制。
  ⇒ 已用 `_snap_reseed.cjs --check` 证明：**10 份快照的 body-hash 完全相同**（D:\civ_soul_data\p1_snaps）
  ⇒ ⇒ **初始状态逐字节相同 ⇒ 只变随机性**（隔离得最干净）
⚠ 恢复路径用 `rng = makeRng(meta.seed + day×2654435761)` ⇒ 换 seed 即换一条随机流
⚠ 代价：结论**条件于这一个初始状态**（不是"跨初始状态"的普遍结论）
```

### 1.2 种子怎么取（不能用 1,2,3…）

```
Weyl 序列（低差异）：seed_k = (20250914 + k × 2654435769) >>> 0
  ⇒ 均匀分散在 32 位空间，相邻间距 ≥ 1.6×10⁹（不是 1,2,3 那种相邻值）
⚠ 但"看起来分散"≠"实测不相关" ⇒ 用**跨种子方差**实测（见 §三）
```

### 1.3 ⚠ 两个不确定性的来源**必须分开报**

```
A · **年内自相关**（within-seed）：同一条轨迹内相邻年份不独立
   ⇒ 朴素配对 t 的 p 偏小（反保守）⇒ 用**移动分块自助（块长 5）**度量
B · **种子间方差**（between-seed）：换一条随机流，效应本身会变
   ⇒ 用**跨种子 E_k 的均值 ± t*(K−1)·SE** 度量 ← **这才是能写进材料的那个**
```

### ⭐ 可归因性的**前提核对**（三点，逐条实测 —— 不是声称）

> "两臂只差一次干预"这句话要成立，必须满足三点。**逐条实测如下**：

| 前提 | 判据 | 实测 | 判定 |
|---|---|---|---|
| ① **初始状态完全相同** | 各快照 body（数组块）SHA256 应**全同** | 唯一值 **1/5** | ✅ **成立** |
| ② **只有 seed 变**（`day` 必须一致） | 各快照 `meta.day` 应**全同** | 唯一值 **1/5**（day = 730） | ✅ **成立** |
| ③ **两臂用同一份快照** | 同一 `k` 的 ctrl/treat 记录的 `seed` 应相同 | 5 对中 **5** 对相同 | ✅ **成立** |

```
· ①② 是**恢复路径的硬前提**：`rng = makeRng(meta.seed + meta.day × 2654435761)`
  ⇒ `day` 若不同，换 seed 就不再是"只变随机流"（day 也进了 rng 种子）
· ③ 的判据说明：`seed` 的**唯一来源**就是快照的 `meta.seed`
  ⇒ 同一 `k` 两臂记录到相同 seed ⇒ **它们读的是同一份快照**（构造上也是：同一次循环用同一个 `snapFile`）
· 全部三点评判来源：运行期记录的进度文件 + 直接读快照二进制（**不是声称**）
```

## 八、诚实限制

```
· 规模：快照 2,616 人 × 5 年（**小规模**）⇒ 绝对量级不代表长期均衡，只可读方向与幅度
· ⚠ **`coh*`（队列孩次）指标不可引用**：已知只在 ≥40 年的跑里有效
· 干预强度**单档**（未做剂量—反应曲线）
· **可归因性为 L3**（随机流分叉）⇒ 只有**直接链**可作机制结论；
  本报告的"总体效应"仍成立（那正是政府要的），但"为什么"不可归因
· **结论条件于同一个初始状态**（A 方案）⇒ 不是"跨初始状态"的普遍结论
· `CSP1` 有损（15 个数组有精度损失）⇒ 两臂同样受损 ⇒ 不影响**差值**
· 跨种子 t CI 用 df=K−1=4 ⇒ 自由度小 ⇒ CI 偏宽（**保守方向**，可接受）
```

## 八·补、⚠ 方法学教训（**本次最该带走的一条**）

```
❌ 我犯的错：冒烟测试**只测了"零干预"路径**（`-`），没测"带干预"路径。
   ⇒ 于是 `SOUL_INTERVENE` 的语法错误（逗号后的项缺 `kind:` 前缀）**躲过了冒烟**，
     在正式批次里才暴露：treat 臂 **1 秒即退出**，而 ctrl 臂正常跑完 398 秒。
   ⇒ 更隐蔽的是：**ctrl 臂全部成功** ⇒ 进度文件"看起来在推进" ⇒ 若不看 ok 字段，
     会以为批次正常，直到最后才发现一半的臂是空的。

✅ 根因（与本项目已累计抓到的 **6 类"静默失效"同一条**）：
   **凡"只在一条路径上验证过"的机制，另一条路径就有静默失败的空间。**
   前 6 类：① 从未接上注入钩子 ② 死注入 ③ 数据文件脱同步 ④ 45 处锚点静默不生效
           ⑤ 2 处 replace 静默 no-op ⑥ 引擎零处"缺字段告警"
   ⇒ 第 7 类（本次）：**冒烟只覆盖无干预路径**。

⇒ 建议（很轻，但能防一整类问题）：
   · `_fork_compare.cjs` 应自带一个 **"带干预"的端到端冒烟自检**
     （`_intervene_selftest.cjs` 是 33/33 的**单元**级；缺的是**端到端**那一条）
   · 判据：**干预臂必须真的产出与对照臂不同的产物**（SHA 不同），否则报错退出
   · 编排器（本工具链）应在**每臂结束后立刻断言 `ok`**，失败即**停止批次**而不是继续
     ⚠ `_multiseed.cjs` 当前是"记录 ok 并继续" ⇒ 已可改进（断点续跑会重跑失败的臂，不会丢数据）
```
