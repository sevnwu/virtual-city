# `_selfcheck.cjs` — 逻辑自洽性检查器 · 用法与语义

> **动机（用户的洞见）**：「**这种 bug 在设计之初就该检验得到**」。
> 而它们**全是纯逻辑错误** —— **不依赖任何外部数据/标定**，
> 只需要**把模型的输出读一遍 · 检查它自洽不自洽**。
>
> ⚠ **与判据 A/B/C 的关系**：判据 A/B/C 是**单点验证**（"这个改动生效了吗"）；
> 本检查器是**一致性验证**（"多个机制一起跑 · 会不会打架"）。**两者互补 · 缺一不可。**

---

## 一、⭐ 什么时候跑

```
⭐ **每次改引擎后** —— 与判据 A/B **并列**（**不是"有空再说"**）✓
   ⇒ ⚠ **因为它抓的是判据 A/B 【抓不到的那一类】**：
     **判据 A/B 全过 · 而模型内部自相矛盾** ✓
⇒ ⭐ **成本极低**：**只读产物 · 零算力 · 可与任何批次并行** ✓
```

## 二、怎么用

```bash
node D:\civ_soul_data\_selfcheck.cjs <结果目录> [--max N]
# 例：
node D:\civ_soul_data\_selfcheck.cjs D:\civ_soul_data\govB2_treat_sh
node D:\civ_soul_data\_selfcheck.cjs D:\civ_soul_data\rcC_on_sh --max 300
```

**⭐ 退出码语义（很重要 —— 必须区分这四种）**：

| rc | 含义 | 怎么读 |
|---|---|---|
| **0** | ✅ **查过了 · 无违规** | **可以放心**（**但要确认没有"未执行"项**） |
| **1** | 🔴 **查过了 · 有违规** | ⭐ **看具体条目** |
| **2** | ⚠ **用法/输入错误**（目录不存在 · 找不到 lives 文件 · 找不到 `events` 字段） | **不是"通过"** |
| **3** | ⚠⚠ **检查未执行** | ⭐⭐ **必须读成"【未能验证】"· 绝不是"没问题"** |

> ⭐⭐ **rc=3 是本检查器最重要的设计** ——
> **"0 例"可能只是"检查器没跑"**（同族于**"两臂相同有四个原因"**·**"无日志≠未生效"**）。
> **一个永远报"✅ 通过"的检查器 · 比没有检查器更危险**（因为它给虚假的安全感）。

## 三、它检查什么

```
**C1 时间线单调**    : `events` 的 `day` 非递减
**C2 在押期间禁约会** : ⭐ **`jailUntil > day` 的窗口内不应出现「约会/交往/分手/婚外情」**
                     —— **这是用户在演示页上发现的那条** ✓
**C3 死亡后无事件**  : `deathDay` 之后不应再有事件
**C4 出生早于事件**  : 事件 `day` 不应早于出生 `day`
**C5 羁押倒计时为正**: ⚠ **尚未实现**（若出现"还剩 N 天"· N 应 > 0）
```

## 四、⚠⚠ 它现在**查不到**什么（**已知限制 · 必读**）

```
🔴 **它需要【含 `events` 的导出】· 而离线产物里【没有】**
   ⇒ **实测确证**：`A_lives_*.jsonl.gz`（含分片形态 `A_lives_<startDay>_<Nd>.jsonl.gz`）
     **是【转世台账】· 不是一生轨迹** ✓
     实测字段：`sid · life · birthDay · deathDay · ageAtDeath · L1_start/L1_end/L1_peak · **ev={}（空）**`
   ⇒ ⇒ ⭐ **所以 `ev` 为空 ⇒ 所有 C 检查【未执行】⇒ 报 `rc=3`** ✓
   ⇒ ⚠ **而演示页上那个"生活/工作轨迹"是【引擎按需实时算的】**
     （`routineOverlayDate` + `cityRoutine`）
     ⇒ ⇒ ⭐⭐ **要检查它 · 必须【跑起来的城市】或【含 `events` 的导出】** ✓✓
⇒ ⭐ **所以"在押约会"这个 bug · 用现有离线产物【验证不了】** ——
  **而它的修复归属只能靠【修复前后判据 A 对照】间接证明**（**已做 · 见 `DETAINED_FIX_REPORT.md`**）✓
```

## 五、⭐⭐ 两条使用纪律

```
① ⭐⭐ **"检查器必须先自证能失败"**
   ⇒ **拿一个【已知有问题】的样本喂它 · 看它会不会报错** ✓
   ⇒ ⚠ **一个从不报错的检查器 = 没有检查器**（**甚至更糟：虚假安全感**）✓
   ⇒ ⭐ **本检查器的"自证"方式**：**缺字段的样本 ⇒ 应报 rc=3**（**已实测**）✓

② ⭐ **"未执行"必须与"通过"分开报** ——
   ⇒ ⚠ **2026-10-07 修过一次**：初版 C2/C3/C4 在字段缺失时会报"✅ 0 例"（**假通过**）·
     **现在会显式报【未执行】并以 rc=3 结束** ✓
```
